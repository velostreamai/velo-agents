## What the PR does
Adds a per-worktree code-discovery index (`zg` / zvec-grep) built synchronously by
`velo-dispatch` before the worker launches, a `zg` shim so the command the policy
names actually exists, brief-spec and impl-policy documentation, and git
exclusion for the index.

## Already found and fixed in b171e40f8 — verify the fix, do not re-report
The `.gitignore` entry protected only branches containing it. Every worktree on
disk predates the merge, so `.zvec-grep/` (325MB) was untracked there, and
`velo_runner_lib.salvage_on_failure()` runs `git add -A` then commits — the
failure path would have committed the index. Fixed by writing the patterns to the
git common dir's `info/exclude` at dispatch.

**Attack that fix**: is `git rev-parse --git-common-dir` reliable from a linked
worktree, from the main repo, and when `$WT` is not a repo at all? The relative-
path branch (`[[ "$GIT_COMMON" = /* ]] || GIT_COMMON="$WT/$GIT_COMMON"`) — is it
correct, or does it build a wrong path in some case? What if `info/exclude` is a
symlink, read-only, or the repo is a submodule?

## Primary targets
1. **The synchronous 35s index build.** It runs before dispatch on every job. What
   happens on `timeout 300` expiry, on a full disk, on a worktree with no Rust,
   when `zg` is present but broken, when two dispatches race on the same tree?
   Is any of it fatal to a dispatch that would otherwise succeed?
2. **The `zg` shim.** It prefers a global install and falls back to
   `npx --yes @zvec/zvec-grep@latest`. Attack: is the fallback silent? Does a
   worker calling `zg` get a clear failure or an empty result set that reads as
   "no matches"? An unanswerable query that looks like a negative answer is the
   exact failure mode the PR's own comments say it is avoiding.
3. **Disk.** 325MB per worktree × 8 worktrees, on a machine with a KNOWN
   worktree-disk-exhaustion problem (~20GB target/ each). Is anything cleaning
   these up? Is there a check before building?
4. **`velo-impl.md` / `velo-brief-spec.md`**: do the documented `zg` invocations
   match what the shim actually accepts? Run them.
