# Scope — PR #2027, review round 7

## What this PR is
`velo-dispatch` preflight: refuse a dispatch when the brief's declared BRANCH /
WORKTREE do not match what the dispatch will actually cut. Plus `velo-pr-gate`
health checks (#2005).

## Read this before reviewing
Six prior rounds. **Every one found a real defect, and every defect was in an
attack point the author had written down and then not executed.** The failure
mode of this PR is not subtlety — it is claims made without running them.

Round 6 is the one to calibrate against: the round-5 fix **deleted the WORKTREE
comparison outright**. It replaced the block from `if [[ -z "$BRIEF_WT" ]]`
through the success line, and the mismatch check was inside that slice. A wrong
worktree then printed `ok brief BRANCH/WORKTREE match what will be cut`. The
feature the PR exists to add, removed by a fix to that feature, still reporting
success. The author's test suite did not notice, because it exercised the
extractor helpers in isolation — every helper returned the right value; nothing
compared them.

## Your job this round
1. **Re-derive the guarantee from the code, do not trust the diff's narrative.**
   For each of: empty BRANCH, empty WORKTREE, absent field, present-but-wrong
   BRANCH, present-but-wrong WORKTREE, trailing slash, trailing whitespace,
   symlinked path, `~` unexpanded — say which branch of the real script handles
   it and what it prints. Any path reaching the `ok` line with a wrong value is a
   P1.
2. **Attack the new test** (`.agents/tests/test_dispatch_preflight.sh`). It is
   supposed to be the thing that would have caught round 6. Does it actually
   drive the real script? Can it pass while the comparison is absent? What does
   it do when `VELO_TEST_ISSUE` is unset — skip loudly, or pass silently? A test
   that green-lights a missing check is the round-6 defect in a new location.
3. **Check the shared-script surface.** This PR touches `velo-dispatch` and
   `velo-pr-gate`, and two other open PRs (#2028, #2033) touch the same files.
   Flag anything here that a rebase of those would plausibly clobber or silently
   revert.
4. `velo-pr-gate` changes (#2005): does the health check actually fail when the
   condition it names is true? Prove it, don't read it.

## Verdict
State P1/P2/P3 per finding with the exact reproducing invocation. If you find
nothing, say what you executed to reach that — "looks correct" is not a result
this PR has earned.
